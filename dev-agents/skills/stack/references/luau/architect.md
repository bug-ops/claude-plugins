# Luau — Architect Rules

Luau types are structural and erased at runtime, so every invariant needs a type-level encoding AND one runtime construction point (a validating constructor) at the trust boundary. On Roblox the biggest trust boundary is the network: everything a client sends through a remote is attacker-controlled. Lua mode: express the same designs with LuaLS annotations (`---@class`, `---@alias`, `---@param`) and lean harder on runtime constructors and `assert`-based contracts.

## Type-Level Toolkit

| Invariant | Luau construct |
|-----------|----------------|
| Domain value (id, currency amount) | Type alias + one validating constructor; when two id kinds must not mix, a frozen wrapper table with a singleton tag (`{ kind: "UserId", value: string }`) |
| Closed set of alternatives | Tagged union on a singleton string field (`kind: "idle" \| "running"`), refined with `if v.kind == ...`; a final `error` branch names the unhandled tag |
| Fallible operation | `Result<T, E>` tagged union (`{ ok: true, value: T } \| { ok: false, err: E }`), or a Promise when the project uses one |
| State-machine correctness | One type per state with a singleton tag; transition functions accept only the valid source state type |
| Immutable data | `table.freeze` at construction; `read` property modifiers only where the new type solver is enabled (`toolchain.md` **Type solver**) |
| Object with behavior | Metatable class with an exported instance type `typeof(setmetatable({} :: Data, Class))` |
| Type chosen by the caller | Generic function `<T>` or generic type alias |
| Constant tables checked against a type | Annotate the table (`local Specs: { [Key]: Spec } = { ... }`) and freeze it |

```luau
--!strict
export type ParseError = { kind: "empty" } | { kind: "tooLong", max: number }
export type Result<T, E> = { ok: true, value: T } | { ok: false, err: E }
export type UserId = { kind: "UserId", value: string }

local function parseUserId(raw: string): Result<UserId, ParseError>
	if #raw == 0 then
		return { ok = false, err = { kind = "empty" } }
	end
	if #raw > 64 then
		return { ok = false, err = { kind = "tooLong", max = 64 } }
	end
	return { ok = true, value = table.freeze({ kind = "UserId" :: "UserId", value = raw }) }
end
```

The wrapper costs one allocation: use it where mixing ids is a real risk, a plain alias plus constructor elsewhere. External data (remote arguments, `HttpService:JSONDecode`, DataStore values, `@lune/serde` output, `io.read`) is `unknown` until a validator checks it; use the project's validator (`t`, a hand-written guard module, or generated network code) and derive the static type once. No `isValid()` on a constructed value.

Class pattern the type checker understands:

```luau
local Account = {}
Account.__index = Account

type AccountData = { balance: number }
export type Account = typeof(setmetatable({} :: AccountData, Account))

function Account.new(): Account
	return setmetatable({ balance = 0 }, Account)
end

function Account.deposit(self: Account, amount: number)
	assert(amount > 0 and amount == amount, "amount must be a positive number")
	self.balance += amount
end

return Account
```

## API Naming

- `PascalCase` for modules that return a class or service table, Roblox instances, and types; `camelCase` for locals, functions, and methods — or the Roblox engine style (`PascalCase` methods) when the project follows it. Match the project; never mix within a module.
- Constructors `X.new(...)`, alternative factories `X.fromY(...)`; conversions `toX()`; predicates `isX`/`hasX`.
- Yielding functions are named or documented as such (`fetchProfileAsync`, or a Promise-returning `fetchProfile`) — a caller must know a call can suspend.
- Options tables over positional optional parameters once a function has more than two.
- Module return values: return one table (or one function) and never mutate it after return; no global assignments.

## Scale-Appropriate Layout

| Scale | Project strategy | Type complexity |
|-------|------------------|-----------------|
| MVP/Prototype | One Rojo project, `server`/`client`/`shared` folders | `--!strict` everywhere, tagged unions |
| Small | + one remotes module defining every remote and its payload type | + validators at every remote and DataStore boundary |
| Medium | Several places or a shared package, Wally/pesde dependencies, typed network layer (generated by an IDL such as Zap or Blink when the project uses one) | + state types for sessions, matches, inventories |
| Large | Multiple places per experience, internal packages published to a private registry or vendored, CI-driven deploys through Open Cloud | Full type-driven design, API reports per package |

**MVP / Prototype** (Roblox, Rojo):
```
my-game/
├── default.project.json   # maps src/ into the DataModel
├── rokit.toml             # pinned tools: rojo, wally, stylua, selene, luau-lsp
├── wally.toml             # dependencies (Packages/ is generated, never committed)
├── selene.toml, stylua.toml, .luaurc
└── src/
    ├── server/            # → ServerScriptService
    ├── client/            # → StarterPlayer.StarterPlayerScripts
    └── shared/            # → ReplicatedStorage.Shared
```

**Standalone Luau (Lune) or Lua library:**
```
my-lib/
├── .luaurc                # aliases and language mode (Luau); .luarc.json (Lua)
├── src/init.luau          # the package entry point
├── tests/
└── pesde.toml | wally.toml | my-lib-1.0.0-1.rockspec
```

## Project Conventions

Defaults — follow the project's existing convention when one exists:

1. **One toolchain manager** (`rokit.toml`) pins every CLI version; CI installs from it.
2. **Generated code is never edited**: `Packages/`, `ServerPackages/`, `DevPackages/` (Wally), `roblox_packages/` (pesde), `sourcemap.json`, roblox-ts output (`out/`), IDL-generated network modules.
3. **Realm boundaries**: server-only code and secrets live in `ServerScriptService`/`ServerStorage`; `ReplicatedStorage` holds only code the client may read — every replicated module is downloadable by any player.
4. **Dependency direction**: `shared` imports nothing from `server` or `client`; `client` never requires server modules. Services do not require each other in cycles — `require` cycles error at runtime on Roblox.
5. **Single entry points**: one server Script and one client LocalScript that require and start modules in a defined order, instead of many independent scripts racing each other.

## Public API Surface

- The module's return table is the API. For packages, `init.luau` returns it; Wally `include`/`exclude` and pesde `includes` decide what ships.
- Re-export public types from the entry point (`export type X = Impl.X`); everything exported is API: renaming a field, narrowing a parameter, or adding a required option is breaking.
- Wally `realm` (`shared` vs `server`) is part of the contract; a server-realm package can never be required from the client.
- Lua libraries: the rockspec `build.modules` table lists every installed module; anything listed is public.

## Runtime Targets

- **Roblox**: decide per module whether it runs on the server, the client, or both (`RunService:IsServer()` checks inside shared code are a smell — split the module). Script `RunContext` must match the folder the script lives in.
- **Parallel Luau**: CPU-heavy work goes into `Actor`s; code inside runs in parallel only after `task.desynchronize()` and may not write to the DataModel there. Design the message format (`Actor:SendMessage`, `SharedTable`) up front.
- **Lune / standalone Luau**: tooling, build scripts, and pure-logic tests; `@lune/roblox` reads and writes place files outside Studio.
- **Lua**: pick the floor (5.1/LuaJIT, 5.3, 5.4) and record it in the rockspec `dependencies` and `.luarc.json` `runtime.version`. Luau code does not run on PUC Lua and vice versa (`goto`, `<close>`, integer subtype vs `continue`, compound assignment, type annotations).

## Async Concurrency Patterns

| Pattern | Use Case | Primitive |
|---------|----------|-----------|
| Start a thread now | Fire-and-forget work owned by a service | `task.spawn` (errors surface in the output, not to the caller) |
| Start after the current resumption cycle | Avoid re-entrancy from inside event handlers | `task.defer` |
| Wait / delay | Timers, throttling | `task.wait(s)`, `task.delay(s, fn)`, cancel with `task.cancel(thread)` |
| Compose yielding work | Load profile and inventory together, with timeout | Promise library (`Promise.all`, `Promise.race`, `:timeout(s)`, cancellation) when the project uses it |
| Event fan-out | Domain events inside one realm | `BindableEvent`, or a pure-Luau signal module |
| Client ↔ server | Requests and notifications | `RemoteEvent` (fire-and-forget), `UnreliableRemoteEvent` (lossy high-rate state), `RemoteFunction` server-side only for client→server requests |
| CPU-bound work | Pathfinding, terrain, procedural generation | Parallel Luau `Actor`s |

Cleanup is part of the design: every `Connect` has an owner that disconnects it (a cleanup object such as Trove/Janitor/Maid, or `Instance:Destroy()`), and every spawned thread has a cancellation path. Never use `RemoteFunction:InvokeClient` — a client can hang or error the server thread.

## Checklist Additions

- [ ] Realm of every module decided (server / client / shared); secrets and authority only on the server
- [ ] Every remote listed in one place with its payload type, validator, and rate limit
- [ ] Persistence design: DataStore keys, session locking, schema version and migration path
- [ ] Runtime floor decided (Roblox only, Lune, or a Lua version) and recorded
- [ ] Trust boundaries identified, each with one validator
- [ ] Module dependency graph acyclic; `shared` depends on nothing realm-specific

## Tools

Beyond `toolchain.md` (type check, lint, format):

```bash
rojo sourcemap default.project.json -o sourcemap.json   # DataModel paths the type checker resolves requires against
rojo build default.project.json -o build.rbxl           # proves the project tree maps cleanly
selene .                                                # includes unused-variable and shadowing checks
rg -n "require\(" src | sort                            # quick dependency graph; look for client→server edges
```

## Anti-Patterns

- `--!nonstrict` or `--!nocheck` in new modules; `any` in public types
- Server logic, secrets, or anti-cheat checks in `ReplicatedStorage` or client scripts
- Trusting remote arguments (types, ranges, ownership) or client-reported positions, prices, and damage
- Dozens of independent Scripts with implicit start order instead of one entry point per realm
- Optional-field bags (`{ loading: boolean?, data: T?, err: string? }`) where a tagged union encodes the valid states
- Global variables and `_G`/`shared` as a service locator
- `getfenv`/`setfenv`/`loadstring` — they disable Luau optimizations and widen the attack surface
- `require` cycles, or modules that yield at require time (`WaitForChild` chains at the top level of a shared module)
- Deep metatable inheritance chains where composition or a tagged union would do
